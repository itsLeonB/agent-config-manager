# agent-config-manager

Dashboard that inventories your Claude Code setup (plugins, MCP servers,
skills, environment tools, project scope) across local machine and claude.ai
cloud. See [README.md](README.md) for what it does and how to run it.

## Migration history

This was originally a static `index.html` + `app.js` page (`fetch()` of
`database/*.json`, rendered with hand-written DOM string templates). It was
migrated to TanStack Start (React + TypeScript) on 2026-08-30, scaffolded
fresh rather than converted in place.

Scaffold command used:

```
npx @tanstack/cli@latest create my-tanstack-app --agent --package-manager bun --tailwind
```

(`--tailwind` is now a no-op — Tailwind ships by default in TanStack Start scaffolds.)

Scaffolded in a scratch directory, then merged into this repo: `package.json`,
`tsconfig.json`, `vite.config.ts`, `tsr.config.json`, `bun.lock`, `.cta.json`,
`.vscode/`, `src/`. `database/`, `.claude/`, `.remember/`, `LICENSE`, and git
history were left untouched.

Follow-up TanStack Intent commands run against the scaffold before writing
any app code:

```
npx @tanstack/intent@latest install   # generated AGENTS.md skill-loading block
npx @tanstack/intent@latest list      # 31 skills across 9 packages
```

Skills loaded and applied: `start-core`, `router-core`, `router-core/data-loading`,
`start-core/server-functions`. Per `AGENTS.md`, run
`bunx @tanstack/intent@latest list` before future substantial changes and load
the matching skill before editing — don't guess at current TanStack patterns.

## Stack

- React 19 + TypeScript, TanStack Start (file-based routing under `src/routes/`)
- Bun for package management and running scripts (`bun install`, `bun dev`, `bun run build`)
- Tailwind v4 is wired up (`src/styles.css`) but unused by the dashboard itself —
  the dashboard keeps its original hand-written CSS (dark/light via
  `prefers-color-scheme`, no toggle) for pixel-identical UX. Left in place
  for any future page that wants it.
- `scan.cjs` / `scan.test.cjs`: unchanged Node CLI scanner, **not** migrated —
  it's a separate offline data-generation script, not part of the "renderer."
  Renamed `.js` → `.cjs` because the new `package.json` sets `"type": "module"`
  and the script uses `require()`.

## Architecture decisions

- **Data loading is server-only, not client `fetch`.** `src/server/dashboard.server.ts`
  reads `database/local.json` / `database/cloud.json` from disk via `node:fs`;
  `src/server/dashboard.functions.ts` wraps that in a `createServerFn`; the
  index route's `loader` calls it. This follows the TanStack Start Intent
  `data-loading` skill: loaders are isomorphic (run on client too), so
  filesystem access must live behind `createServerFn`, and a loader must not
  self-fetch a relative URL during SSR.
- **`src/types/dashboard.ts`** defines the `local.json`/`cloud.json` shapes
  (kept in sync with `scan.cjs`'s output, not derived from it) plus a `Json`
  recursive type — TanStack Start's server-function return type must be
  provably serializable, so `mcpJson`/`pluginInstalls` can't be typed `unknown`.
- **One component per original render function** in `src/components/dashboard/`
  (`PluginsCompare`, `McpList`, `SkillsCompare`, `EnvironmentTools`,
  `ProjectsTable`, `CloudBanner`, `MissingCell`), composed by `Dashboard.tsx`.
  This mirrors `app.js`'s existing modularity rather than inventing new
  structure.
- **localStorage-backed "missing" comments** and the **clipboard copy-install-script
  button** are ported behavior-for-behavior (`src/lib/comments.ts`,
  `src/lib/install-script.ts`) — still per-browser, still no backend write.
- Removed the scaffold's demo content (`Header`/`Footer`/`ThemeToggle`
  components, `/about` route, marketing landing page, Google Fonts import,
  `@tailwindcss/typography`) — none of it applies to a single-page dashboard.

## Environment variables

None required. All data comes from local files (`database/local.json`,
`database/cloud.json`) generated by `scan.cjs` and `/refresh-cloud`.

## Deployment notes

Not yet deployed anywhere. `bun run build` produces `dist/client` + `dist/server`
(Node SSR server output) via Vite. Since the app reads `database/*.json` from
the local filesystem at request time, a real deployment target needs either:
that directory present on the server's disk, or the data-loading layer
swapped for a different source — not yet decided, this app has only run
locally so far.

## Known gotchas

- `database/` is gitignored (real, locally-scanned config) — a fresh clone
  has no data until you run `node scan.cjs` at least once. The dashboard
  shows "database/local.json not found. Run: node scan.cjs" until then.
- `cloud.json` is populated by the agent-driven `/refresh-cloud` slash command
  (browser automation against claude.ai), not by any code in this repo.
- TanStack Devtools in `src/routes/__root.tsx` are auto-stripped from
  production builds by `@tanstack/devtools-vite` — confirmed via `bun run
  build` output ("Removed devtools code from: /src/routes/__root.tsx"), no
  manual `removeDevtoolsOnBuild` config needed.
